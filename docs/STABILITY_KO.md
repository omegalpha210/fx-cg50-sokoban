# beta.4 안정성·오류 검증

호스트 검증에서 크래시나 UBSan 오류를 재현하지 못했습니다. 실제 CG50 펌웨어를
실행한 검증은 아니므로 실기에서 절대 튕기지 않는다는 의미는 아닙니다.
새 OS 절전 호출, 실제 LCD 단계, OFF/ON 복귀는 **실기 미검증**입니다.

## 메시지가 나타나는 조건

| 상황 | 화면·동작 | 보존·복구 |
|---|---|---|
| 처음 실행하며 두 저장 파일이 모두 없음 | 메시지 없이 Main | 정상적인 새 진행 |
| 한 슬롯이 손상되거나 읽기 실패, 다른 슬롯 사용 가능 | BACKUP RECOVERED | 검증된 슬롯 사용, EXE/EXIT로 계속 |
| 우선 슬롯을 다시 읽는 중 실패하고 다른 슬롯 사용 가능 | BACKUP RECOVERED | 다른 검증된 슬롯으로 복구 |
| 기존 슬롯이 모두 손상됨 | SAVE UNAVAILABLE | 새 진행으로 시작, EXE/EXIT로 계속 |
| 유효한 슬롯이 없고 열기·크기·읽기·닫기에서 I/O 실패 | SAVE UNAVAILABLE | 새 RAM 진행. 나중에도 안전한 대상 슬롯을 확인할 수 없으면 저장 거절 |
| INIT 확정, 완료, 플레이 EXIT, 레벨 이동, MENU에서 저장 실패 | SAVE FAILED | EXE 재시도, F6 저장 없이 진행, EXIT 현재 화면에 머무름 |
| 수동/자동 OFF에서 저장 실패 | 한 번 시도 후 OFF 진행, ON 복귀 때 SAVE FAILED | 이전 유효 저장본과 dirty RAM 유지. 종료를 대화상자로 막지 않음 |
| SAVE FAILED에서 MENU | 다시 저장 시도, 성공하면 OS 메뉴 | 실패하면 오류 화면 유지. F6으로 저장 없이 OS 메뉴 이동 가능 |

SAVE FAILED에는 다음 원인이 포함됩니다: 안전한 슬롯을 읽지 못함, 저장 데이터
검증/인코딩 실패, 세대 번호 한도, 대상 삭제·생성·열기 실패, 0바이트/오류/비정상
길이 쓰기, 닫기 실패, 재개방·읽기·EOF·바이트 대조 실패. 저장 공간 부족은 OS의
생성/쓰기 오류로 이 경로에 들어갑니다. 저장 파일의 CRC만 맞아도 허용하는 것이
아니라 맵 식별자·레벨·좌표·상자·카운터·UNDO까지 검증합니다.

확정한 INIT 후 저장 실패에서 EXIT를 눌러도 INIT 이전으로 되돌리지는 않습니다.
이미 클리어한 기록은 저장 실패 시에도 RAM에 남습니다. F6은 저장 성공으로
표시하지 않으며 dirty를 지우지 않습니다. 장시간 OFF로 RAM이 사라지거나 실제
전원이 끊기면 마지막으로 성공한 저장 이후의 진행은 없어질 수 있습니다.

## 오류나 크래시가 아닌 동작

- 벽·상자 둘·막힌 상자 밀기: 이동하지 않고 카운터/UNDO도 변하지 않습니다.
- 성공 창에서 EXIT: 완성된 보드만 보여 줍니다. 방향키·INIT·UNDO는 잠기며 두 버튼은 회색입니다.
  F5/F6 이동과 MENU/OFF는 가능합니다. 다시 EXIT 후 해당 레벨을 열면 클리어 표시를 유지하고 새로 시작합니다.
- UNDO 없음, 레벨 1의 LEVEL-, 레벨 60의 LEVEL+: 동작하지 않으며 버튼을 흐리게 표시합니다.
- 같은 제어 키를 계속 누름: 중복 실행을 막습니다. 화면 전환 후에는 놓고 다시 누릅니다.
- MOVES가 32비트 최대값이면 추가 이동을 거절합니다. UNDO/INIT으로 진행할 수 있습니다.
- 일정 시간 후 화면이 어두워지거나 전원이 꺼짐: SYSTEM 설정을 따른 정상적인 절전입니다.
- 알 수 없는 시간 설정값: 10분/30초로 대체합니다. 정상 밝기값을 읽지 못하면 밝기 변경은 생략합니다.

## 종료·시스템 오류와 구분할 조건

프로젝트 화면은 재귀 호출하지 않고 하나의 main 루프로 계속 동작합니다.
자체 코드에는 게임 도중 의도적으로 프로세스를 종료하는 경로가 없습니다.
단, 설치된 gint의 `src/keysc/keysc.c::keysc_tick()`에는
**SHIFT + 7 + 3 + AC/ON**을 함께 누르면 `abort()`하는 강제 탈출 조합이 있습니다.
이 조합은 정상 저장을 거치지 않으며 일반 SHIFT + AC/ON과 다릅니다.

실제 펌웨어 호출 자체의 중단, 전원 손실, RAM 소실, OS/하드웨어 예외는 호스트
모형에서 재현했다고 주장하지 않습니다. 특히 새 백라이트 syscall의 CG50 단계 0과
지정 밝기 복원, 실제 파일시스템의 닫기 실패, 장시간 OFF 후 새 실행은 실기 확인 대상입니다.
오류 재현 시 OS 버전·레벨·직전 키·화면 메시지·OFF/ON 여부와 저장 두 파일을
보존하면 원인을 좁히는 데 도움이 됩니다.

## 수행한 자동 검증

- 엔진: 60개 맵에서 76,275회 성공 이동, 1,500회 밀기 및 UNDO; 359,247 assertions.
- 워크플로: 메뉴·모달·저장 성공/실패·OFF를 섞은 100,000개 이벤트와 정해진
  경계 사례; 총 333,615 assertions. 각 단계에서 활성 보드와 저장 진행을 검증합니다.
- 실제 native BFile 어댑터: 한 저장 과정의 48개 및 로드 과정의 57개 호출 지점에
  오류를 하나씩 주입합니다. 이전 유효 슬롯, 실패 시 RAM/세대 번호, 닫기와 재시도를 확인합니다.
  전체 모형 실행은 215개 OS transaction / 9,026개 BFile 호출입니다.
- 저장: 60레벨 왕복과 5회 UNDO 복구, 모든 길이의 잘린 데이터, CRC·맵 해시·좌표·
  상자·UNDO 손상, 한 슬롯 복구, 두 슬롯 실패, 재시도와 세대 번호 한도를 검사합니다.
- 절전: 6개 시간 설정 조합 × 3개 시작 시점의 모든 128Hz tick을 검사합니다.
  자정 경계, 키 누름/놓음/반복/미사용 키, 모든 화면의 자동 종료, 설정 재읽기를 포함합니다.
- 화면: 전체 60개 맵을 포함한 87개 캡처에 화면 밖 그리기가 없으며,
  네 그룹 플레이어 9~19px의 색 면적과 경계를 검사합니다. README는 실제 1/16/31/59번 맵이며,
  1번 시작부터 394회 정상 이동으로 완료·EXIT 후 잠금·레벨 선택 후 재도전을 확인합니다.
- 엄격한 SH 컴파일, C/UBSan 10개 suite, Python 41개 test와 G3A 16개 검사를 사용합니다.
  ASan은 기존 호스트 런타임 문제로 미검증입니다. 실제 메모리 여유/총 스택 피크는
  단일 함수 frame 크기나 UBSan으로 입증되지 않습니다.
